# Prompt: rebuild Hack Dev Code from DeepSeek Harness

Copy everything below the line into a coding agent (Claude Code or similar) running on a Windows 11 machine with Git, Node.js 24.9+, pnpm 11, Visual Studio Build Tools (C++), Windows PowerShell 5.1 and Ollama installed. Run it from an empty folder.

---

You are a senior engineer turning the open-source **DeepSeek Harness** agent runtime (MIT) into a production desktop product called **Hack Dev Code**: an AI agent that codes and operates the Windows or Linux desktop and the browser the way a person does. It runs on any model (local Ollama models, DeepSeek, or any OpenAI-compatible provider) and is extended through skills, plugins, MCP servers and connectors, like Claude.

The agentic system stays the official DeepSeek Harness one. Keep its agent loop, subagents, workflow engine, tool runtime and orchestration as upstream designed them. Do not add your own multi-agent pipeline. Your work is behavior tuning on top of that system, new capabilities, the product layer and fixes.

Work autonomously through every phase below, in order. After each phase run the relevant checks and fix what you broke before moving on. Keep a todo list, update it as you finish each item, and do not stop with items still open.

Before each change, find the current equivalent: search the code and read the package README. Extend what upstream already has (for example its plugin manager, plugin market, skill catalog, MCP client and credential store) instead of building a parallel copy.   - Everything is a Cordis plugin.
  - Tests live next to each package, in `tests/`.
  - Package READMEs keep their "Model Experience" and "Known Limitations and Deferred Work" sections.
  - The client code has a 100% coverage gate.
  - UI strings come from locale files.
  - Lint caps lines at 140 characters.

  1. Run `pnpm install`.

## Phase 3: Models and keys

1. **Key pools: several keys per provider.** Build this into both the DeepSeek adapter and the generic (pi-ai) adapter.
   - The host splits keys on `,` or `;` and drops duplicates. Requests rotate through the keys.
   - A key refused for rate limit, quota or invalidity (401, 402, 403 or 429) rests for a minute. The identical request is resent on the next key.
   - A refusal after output began also rests the key, and marks the step retryable, so the step continues on another key with nothing lost.
   - When every key is resting, the request waits up to a minute for the first one to recover.
   - Honor the provider's `Retry-After` up to 60 seconds, and retry dropped streams.
2. **Fallback models.** Each provider can list `fallbackModels`, used when a model is overloaded or out of quota.
   - The fallback stays in use for that model for a while.
   - Replay signatures stay with the model that answered.
   - A daily quota is final.
3. **Image limits.** When a provider refuses a request for having too many images, drop the oldest half of the images and resend, up to three times.
4. **API key field in Settings → Models.**
   - One row per key: a password input with a show/hide button, and a remove button when there are several keys.
   - Below the rows, **+ Add another key** (disabled until the last row is filled), and the status line "N keys: requests rotate through them, and a key the provider refuses is skipped automatically."
   - Pasting several lines, commas or semicolons splits them into rows. Typing a separator inside a row does not split it.
   - Store only nonblank keys, trimmed and joined with commas. A draft made only of blank rows counts as "no key" and never overwrites a stored key.
   - Tests cover adding, removing, pasting and revealing, at full coverage.
5. **Ollama tab** in the add-provider dialog.
   - It lists the models downloaded on the Ollama server (default `http://127.0.0.1:11434/v1`), all checked.
   - It creates one provider route over Ollama's OpenAI-compatible endpoint, with a placeholder key.
   - Models that report no context window are recorded with `contextWindow: 32768`.
   - Editing the URL clears the list, and the route saves the URL that was actually listed.
   - It shows a clear "Ollama is unreachable" error.
   - The custom provider card also gets one-click presets for Ollama and LM Studio.
6. **Ollama context fix (critical).** Ollama's OpenAI endpoint loads every model with the server's default context of 4,096 tokens and ignores a context size sent with the request. The agent's system prompt and tools are then cut from the front, and the model never sees its tools. For routes on port 11434:
   1. Probe `/api/version`, then read the model with `/api/show`: its trained `*.context_length` and any existing `num_ctx`.
   2. If more context is needed, create the variant `hackdev/<model>:<tag>` once with `/api/create`. Use `from` the original model and set `parameters.num_ctx` to the configured context window, or 32,768 when none is set, never above the trained length. Request that variant from then on; it shares the original's weights.
   3. Routes on port 11434 with no configured context window default to 32,768, so compaction keeps conversations within it.
   4. Cache only settled answers. A failure (Ollama not up yet, or a slow first answer) falls back to the original model for that one request and is retried on the next.
7. **No DeepSeek account sign-in.**
   - Unmount the account sign-in dialog and the Account section.
   - Disable the `llm-deepseek-account` provider row.
   - The desktop welcome and sign-in window is never required: `needsWelcome()` always returns false, and the app opens straight into the workspace.
   - DeepSeek is set up with an API key like any other provider.
8. **No preset default model.**
   - In the base bundle, `agent-default-model` has `provider: ''` and `model: ''`.
   - The session controller settles the default (`ensureUsableDefault`):
     - whenever the model catalog is read;
     - when a session is created or forked and the default is empty or its provider isn't registered. This check has a 10-second limit, so a hung provider can't stall creation.
   - When no default was chosen, or the default's provider lists no models without failing, it saves the first available model. Any provider other than DeepSeek comes first.
   - A provider that failed to list (for example, Ollama is down) keeps its default.
   - The headless bundle explicitly keeps DeepSeek (`deepseek-official` / `deepseek-flash`), because CLI and CI runs use `DEEPSEEK_API_KEY`.
   - A request with an empty provider fails with: "no model is set up yet; open Settings → Models to add a local Ollama model or a provider API key, then pick it in the model menu".
9. **Encrypted keys.** The local credential store seals its file with Windows DPAPI for the signed-in account (`encryptAtRest: true`).

   - It keeps its in-memory copy only after a successful parse.

## Phase 5: Desktop control (Windows and Linux)

Build the whole-desktop tools in the native computer-use driver package.

On Windows, one persistent, hidden Windows PowerShell session compiles a C# helper once. The session restarts after any step that takes longer than 30 seconds. Cancelling never interrupts input that has already started.

### Tools

- **`desktop_list_displays`**
- **`desktop_screenshot`:** captures one window, one display, a region, or everything, scaled to `max_dimension`. Returns the image with its coordinate mapping, and optional OCR.
- **`desktop_pointer`, `desktop_drag`, `desktop_scroll`:** real input on any monitor.
  - Modifier keys can be held during the action.
  - `image_x`/`image_y` take a point from the latest screenshot.
  - `press: down|up` holds a button.
- **`desktop_keys`:** chords such as `win+r` or `alt+tab enter`, with `repeat` and `hold: down|up`.
- **`desktop_type`:** text longer than 500 characters is pasted through the clipboard. Every clipboard format is saved first and restored afterwards.
- **`desktop_window`:**
  - Lists windows and dialogs, including the taskbar ("Taskbar"), secondary taskbars and hidden tray icons, named from their window class.
  - Reads a window through UI Automation (Windows) or AT-SPI (Linux), bounded to 300 elements, 8,000 characters and 4 seconds. Each control is numbered `[n]` with its centre point and state. OCR text is added when a window exposes few controls.
  - Focuses, minimizes, maximizes, restores or closes a window, or moves and resizes it.
  - Waits for a window, or for text to appear in it.
- **`desktop_element`:** finds, clicks, invokes, toggles, expands, selects, sets the value of, or focuses a control by its number, name or automation id (Windows). Falls back to real input or OCR.
- **`desktop_ocr`:** the Windows OCR engine, or tesseract on Linux.
- **`desktop_sequence`:** runs up to 30 steps in one call and stops at the first failure.
- The tools also start apps by name and open files, URLs and settings pages.

### Behaviors (Windows)

- **Windows behind others:** capture and OCR them with `PrintWindow(PW_RENDERFULLCONTENT)` without bringing them to the front, and detect captures that come back blank.
- **Held input:** anything still held down is released when the tools unload.
- **Apps running as administrator:** their windows are marked `[administrator]`, and input to them goes through an administrator helper.
  - The helper starts once per session through the UAC prompt.
  - It runs only a fixed table of commands over a named pipe that only this user can open, and checks the connecting process id and a one-time secret.
  - It exits when the connection closes, or when nobody connects within a minute.
  - The session sends nothing until it has confirmed the pipe belongs to the exact process the UAC prompt started.
  - Its bootstrap checks the script's hash, loads modules only from the system folder, and compiles in a folder only administrators can write to.
- **Secure desktop:** detect when the lock screen or a UAC prompt is showing (`OpenInputDesktop` fails, or the input desktop isn't `Default`). Input refused there tells the agent to ask the person to unlock the computer or answer the prompt.
- **Keep awake:** while the agent operates the desktop, keep the display awake and reset the idle timer every 50 seconds (`SetThreadExecutionState` plus a zero-distance pointer move). Stop 10 minutes (`keepAwakeMs`) after the last input. When a test replaces the script runner, the default is 0 (off).

### Linux

- **X11** uses xrandr, ImageMagick, xdotool and wmctrl.
  - Drags move in steps.
  - Long text is pasted through `xclip`, and the clipboard is restored; without xclip the text is typed.
  - A missing helper is reported with the command that installs it.
- **Wayland** is detected from `XDG_SESSION_TYPE`, or forced with `HACKDEV_DESKTOP_BACKEND=wayland|x11`.
  - Input goes through `ydotool`: kernel key codes, `click 0xC0`-style codes, `mousemove --absolute`, and the wheel.
  - Screenshots come from grim, gnome-screenshot or spectacle. Resize them to the logical desktop size before cropping (for HiDPI screens), then crop and scale with ImageMagick.
  - Clipboard paste uses `wl-clipboard`.
  - Displays come from `wlr-randr --json`, or from XWayland.
  - Windows are listed and managed through `swaymsg` on Sway and `hyprctl` on Hyprland, and through wmctrl for XWayland apps elsewhere. GNOME and KDE get a clear message.
  - Add unit tests for every argument builder and parser.

### Also

- An end-to-end test that drives the Calculator app the way a person would, gated behind `HACKDEV_LIVE_DESKTOP=1`.
- A guidance section for the model covering real input, coordinates, numbered controls and OCR, apps running as administrator, the secure desktop, starting apps, and file dialogs.
- The computer-use bundle is on by default in the Web profile on Windows and Linux.

## Phase 6: Browser control

1. **Built-in browser.** Keep the desktop app's sidebar browser.
2. **Chrome DevTools provider.**
   - Launch mode uses a persistent profile (`isolated: false`), with `vision: true` and `screenshotMaxWidth: 1280`.
   - Its tools are in the on-demand group `chrome`.
   - Performance and emulation tools are off by default.
3. **Connect mode** (the person's own running Chrome, version 144 or later, which asks permission for every new remote-debugging connection). Build a loopback CDP relay inside the provider.
   - **Finding Chrome:** read `DevToolsActivePort` from Chrome's user data directory for the configured channel, with the Windows, macOS and Linux paths, again on every reconnect.
   - **One connection per run:** open the upstream connection on first use and keep it while the provider is loaded, so Chrome asks once per run instead of once per session or subagent. Each session's MCP server connects with `--ws-endpoint <relay>`.
   - **One client at a time:** serve one client at a time, and remap message ids so a new client never receives an answer meant for an old one.
   - **When a client leaves:** turn auto-attach and target discovery off, detach the sessions it attached, and dispose the browser contexts it created (`Target.disposeBrowserContext`). An attach that arrives while no client is connected is resumed (`Runtime.runIfWaitingForDebugger`) and detached.
   - **Security:** the relay's path carries a random 48-hex-character token, and any connection carrying an `Origin` header is refused. That way no other program, and no web page, can drive the person's Chrome.
   - **Clear errors:**
     - "Chrome is not running or remote debugging is off; open Chrome and allow it at chrome://inspect/#remote-debugging"
     - "Chrome declined the connection; click Allow"
   - **Cleanup:** register the relay's cleanup before it starts listening.
   - **Tests** against a fake Chrome:
     - one upstream connection across sessions
     - cleanup when a client leaves
     - reconnecting after Chrome closes
     - a stale port file
     - refusing a missing token and a web-page `Origin`
     - disposing browser contexts
     - handling an attach that arrives with no client

## Phase 8: Skills, plugins, MCP servers and connectors (like Claude)

### 1. Skills

The format is compatible with the open Agent Skills standard: a folder with a `SKILL.md` whose frontmatter holds `name` and `description`, plus optional scripts and resources.

- **Progressive disclosure:** only each enabled skill's name and description are in the system prompt. The full `SKILL.md` and its files load through the skill tool when the agent uses the skill.
- **Scopes:**
  - user: `~/.hackdevcode/skills`
  - project: `.hackdevcode/skills` in the workspace
  - plugin-provided
- **Sources:**
  - a curated skills marketplace index (open-licensed skills)
  - any public Git repository or GitHub `owner/repo[/path][#ref]`, installed by sparse checkout
  - uploading a `.zip` or a folder
- **Create a skill:** an editor for `SKILL.md`, with a frontmatter form and a preview.
- **Per skill:** an enable/disable toggle, update, and remove.
- **Safety:** show the files and scripts before installing. Scripts run under the session's permission mode, like any command.

### 2. Plugin marketplace

A plugin is a bundle that can contain any of these:

- skills
- slash commands (Markdown command files)
- subagent definitions
- hooks
- MCP server definitions
- Hack Dev Code (Cordis) plugin packages, from npm or GitHub `owner/repo#ref` (upstream already supports these)

**Marketplaces** are Git repositories or URLs holding a `marketplace.json` that lists plugins and their sources. Use a format compatible with Claude Code plugin marketplaces (`.claude-plugin/marketplace.json` and `plugin.json`) where practical, and keep upstream's own plugin index format working too. Ship one default curated marketplace, and let the person add or remove marketplaces by URL.

## Phase 9: Make the tests pass on Windows

Make the test suite pass on Windows without weakening what the tests check.

- **`NoDefaultCurrentDirectoryInExePath`:** honor it in the executable resolver, as Windows does. Tests that describe the default search pass an explicit empty environment, or remove the variable for that test and restore it afterwards.
- **PowerShell 7:**
  - Start PowerShell through `resolvePwshPath()` (PowerShell 7 when installed, otherwise Windows PowerShell), never by the literal name `pwsh`.
  - Avoid PowerShell 7-only APIs. For example, check elevation with `whoami /groups | Select-String S-1-16-12288`, which also works in Constrained Language mode.
  - Tests of release tooling that needs PowerShell 7 are skipped, with that reason, when `pwsh` is missing.
  - The sandbox test accepts either `pwsh` or `powershell.exe`.
- **pnpm:** when `npm_execpath` isn't pnpm (the tests were started through npx), run `pnpm` by name, through `cmd.exe` on Windows.
- **tar:** pass archives by a name relative to their own folder. GNU tar reads the drive colon in `C:\…` as a remote host.
- **Redirected app data:** packaged (MSIX) apps can redirect AppData, so test fixtures start from `realpathSync.native` of their temp folder.
- **Package manifests:** compare them by value. Node returns a cached null-prototype object once and a plain object after re-reading.
- **Timing tests:** measure from the event under test (for example, from the cancel), not from before a cold PowerShell compile.
